# Individual growing-edge onboarding

## Understand the starting point

Ask the person what they want to practice, their work context and what a useful change would look like. Invite optional written feedback, performance-review excerpts or another document. Do not require a review, a diagnosis or a manager's participation. Explain the private-storage boundary before saving anything.

For a supplied document, use the host's document-reading capability. Check that the relevant pages are readable; identify missing pages, extraction problems or unreadable scans. Do not infer content from a filename. If reading fails, request a relevant excerpt or an accessible format and continue with the person's description.

## Turn feedback into a proposal

Extract concrete situations and behaviors. For each theme, identify:

- Evidence: a short paraphrase and the actual document/page/section or message reference.
- Interpretation: what habit it might suggest, with uncertainty and plausible alternative explanations.
- Strengths/counterevidence: what already works and any contradictions.
- Proposed practice: an observable action within the person's control.

A single comment is not a personality trait. Do not classify or rank the person. Propose one or two possible growing edges, then ask which feels accurate. With thin evidence, label the focus provisional. An urgent task request can proceed without completing the entire onboarding.

Example: “The feedback describes two changes shared after implementation. A possible focus is earlier alignment on changes affecting others. It may also reflect unclear ownership. Does earlier alignment fit what you want to practice?” This example is fictional.

## Confirm and persist

Agree on one primary edge, desired behavior, situations to observe, success signals, boundaries and a review date. Ask for only the missing details. A success signal might be “before an impactful change, share the proposed approach and decision needed,” not “be a better communicator.”

Use [the profile template](../assets/profile.template.md) only after confirmation. The profile path must be outside all repositories and shared team storage. Verify that the host can save and reread it. Do not save raw feedback unless explicitly needed and approved. If a private file cannot be written, provide a copyable session profile and explain that persistence has not been configured.

Choose sources with [the sources procedure](sources.md). Onboarding is useful without connectors. Explain which evidence is based solely on the person's account.

## Offer proactive support before finishing

Read [the automation procedure](automations.md). Suggest all three routine types, personalized to the confirmed edge, and let the person select a smaller set or decline:

- Morning: identify upcoming situations to practice the target behavior.
- End of day: identify open loops and one reflection on the behavior.
- Weekly: review evidence, counterexamples and one experiment.

Alignment prompts should focus on dependencies and communication; delegation prompts should focus on ownership and autonomy; strategy prompts should focus on outcomes and assumptions. Do not offer generic reminders with the label changed. Ask for days, local times, IANA time zone and private delivery. Record declined routines so the next session does not repeat the offer unnecessarily.

End with the confirmed focus, profile persistence result, approved source scope and verified routine status. Profile changes later require confirmation. Preserve the existing profile while proposing a revision, and review affected schedules/prompts after a focus change.
