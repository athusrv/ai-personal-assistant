# Privacy and retention

## Shared package versus individual data

Only generic instructions, empty templates and fictional examples belong in this repository. Even a private fork must not contain real growing edges, feedback, reviews, transcripts, personal source links, channel IDs, task IDs, tokens or generated coaching histories. A collaborator with repository access can read committed material and its history.

Use a separate user-controlled directory or a company-approved private storage feature for the real profile, minimal evidence references, automation settings and deduplication state. Never place that directory under this or another repository. Do not use the shared examples as a live profile. Do not copy private content into GitHub issues, pull requests or task descriptions.

## Data use

The person chooses the focus and scope. Query only relevant approved sources and windows, and limit source retention. Reading work context in an AI host sends it through that host's processing and retention policies. A local file is not a guarantee of local-only model processing. Use only services and accounts approved for that material; if policy does not permit analysis, work from a sanitized summary instead.

Do not retain original feedback by default. Store confirmed behavioral goals and a minimal source reference only when needed and allowed. Before retaining reports or deduplication state, agree on what to keep and for how long. Each person can inspect, correct or remove their profile and change their focus. Do not aggregate individual histories into employee analytics or management reports.

## Sending and reminders

A private reminder needs an explicitly enabled routine with an agreed destination. A recipient in a team channel is not private delivery. Never silently switch destinations after a failure. Routine approval does not authorize contacting colleagues, changing events, posting drafts or sharing the profile.

Keep a colleague-facing draft limited to the work decision, question or update. Personal feedback, private interpretations and development labels do not belong in it. Obtain explicit approval for the concrete recipient, destination and content before sending.

## Corrections, pause and deletion

On request, pause the person's routines using the host's controls and verify their status. Updating a profile does not cancel a scheduled task. Removing a task does not delete its previous outputs. Review each store independently: profile, source uploads, reports, task prompts/history, conversations, notifications and host backups. Explain any retention the agent cannot control; do not promise permanent deletion without confirmation from the relevant service. Follow the host's confirmation requirements for irreversible deletion.

## Repository protections

`.gitignore` excludes common private paths, environment files, source-document exports and credentials. It cannot protect files already tracked, material force-added with `git add -f`, or information copied into an allowed file. Review the staged diff and tracked filenames before every commit. Never commit a secret to test detection. If a credential was exposed, revoke it; removing the latest file alone does not remove Git history. Avoid publishing sensitive remediation details into shared channels.
